# Локальный запуск: состояние интеграции

Снимок находится в работе. Сквозной запуск с GitHub, очередью, sandbox и
реальным выполнением тестов ещё не подтверждён. Не используйте его для
автоматического мержа или развёртывания на сервере.

## Демонстрация интерфейса

Нужны Node.js 24 и доступ к npm registry. Из корня репозитория:

```sh
cd frontend
npm ci
npm run dev:mock
```

Откройте адрес, который напечатает Vite. В этом режиме ответы возвращают
локальные моки; результат не является реальным прогоном тестов или мержа.
Проверки интерфейса запускаются командой `npm run check`.

## Backend и инфраструктура

Текущий Compose не готов к запуску как завершённый продукт: постановка задач не
использует Celery как очередь, а сквозная интеграция с runner и sandbox
отсутствует. Реальный GitHub-порт пока не подключён и
отвечает ошибкой, если не включён демонстрационный режим.
Перед общим запуском необходимо устранить эти проблемы и проверить полный поток
на отдельном тестовом окружении. Секреты задаются вне репозитория.

Для проверки конфигурации Compose задайте в окружении `POSTGRES_PASSWORD`,
`TOKEN_ENCRYPTION_KEY`, `SESSION_SECRET_KEY` и `GITHUB_WEBHOOK_SECRET`.
Пароль БД должен состоять из символов, допустимых без кодирования в URL.
Команда `docker compose config -q` проверяет конфигурацию без запуска стека.
API доступен только на `127.0.0.1:8001`; для внешнего доступа требуется
отдельная настройка защиты, которая в этот состав не входит.

Для локальной проверки инфраструктуры на новой пустой базе после задания всех
четырёх переменных можно запустить `docker compose up --build`. Проверка API:
`http://127.0.0.1:8001/health`. Frontend, worker и sandbox этот Compose пока не
запускает; сквозной прогон не работает. Полный запуск Compose ещё не проверен.
`docker compose up` применяет миграцию до запуска API. Начальная миграция
проверена на отдельной пустой PostgreSQL 16: создано 12 таблиц, повторный
`upgrade` и проверка схемы прошли. Не применяйте её к существующей базе без
отдельной оценки. Если старая пустая ревизия уже отмечена как применённая,
требуется согласованное восстановление схемы: повторный `upgrade` сам по себе
её не создаст.
