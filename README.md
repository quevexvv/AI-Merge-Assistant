# AI-Merge-Assistant

> ИИ-ассистент QA-инженера: генерирует тест-кейсы и автотесты по изменениям в ветке, проверяет покрытие нового кода и разрешает мерж, когда условия выполнены.

**Статус:** в разработке. Модули ещё не соединены в рабочий продукт: GitHub,
очередь, изолированный запуск и связь интерфейса с API требуют интеграции.
Текущая версия не готова к развёртыванию и реальному мержу.

Актуальные требования, архитектура, обязанности пяти участников и порядок интеграции: [договор команды](docs/team-guide.md). В разделах ниже ещё есть старые предложения; при расхождении применяется договор команды.

Подключение реализованного LLM-модуля и CLI: [контракт LLM](docs/llm-integration.md).

## Что это

Планируется, что пользователь входит через GitHub, выбирает репозиторий и ветки. Сервис:

1. получает diff между ветками, сообщения коммитов и описание PR;
2. генерирует сценарии в формате Gherkin (Given/When/Then);
3. конвертирует сценарии в автотесты (Python + pytest);
4. проверяет, что сгенерированное валидно (шлюз качества);
5. запускает тесты в изолированном окружении и считает покрытие **нового** кода;
6. при недостаточном покрытии дописывает тесты по непокрытым строкам (несколько итераций);
7. если тесты проходят и покрытие выше порога, разрешает мерж (вручную или автоматически, по настройке).

Планируется также ручной режим загрузки требований и Python-кода без GitHub.

- [ ] Генерация автотестов (Python + pytest)

- [ ] Экспорт `.feature`, `.py`, `.js`
- [ ] QA-дашборд: число тестов, покрытие, успешность прогонов
- [ ] Автомерж по порогу покрытия

## Технологии

- **Backend:** Python, FastAPI, SQLAlchemy
- **Frontend:** см. `frontend/` (стек уточняется)
- **Тесты и покрытие:** pytest, coverage.py, diff-cover
- **LLM:** Google Gemini через `google-genai`, модель и секрет передаются окружением
- **Инфраструктура:** Docker, docker-compose, GitHub Actions

## Структура репозитория
